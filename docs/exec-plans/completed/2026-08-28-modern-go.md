# Modern Go modernization

## Goal

Bring the service lifecycle, cancellation model, error handling, toolchain
declarations, tests, and small standard-library usages in line with Go 1.26.

## Scope

- make signal handling perform bounded graceful shutdown
- propagate request contexts through processing, torrent clients, and notifications
- remove the legacy unsafe error wrapper and use standard errors
- align all build images with the module Go version
- apply the relevant Modern Go Guidelines findings
- add regression coverage for cancellation and shutdown behavior where practical

## Non-goals

- replace Gin, Cobra, zerolog, or torrent-client libraries
- change API payloads or response status contracts
- redesign parse requests as persistent asynchronous jobs
- make context-free upstream qBittorrent calls forcibly cancellable

## Risks

- interface changes affect all torrent-client adapters, mocks, and live tests
- cancellation during import can leave work partially complete in an external client
- error text changes can affect tests or operator-facing logs
- shutdown tests can become timing-sensitive if they use real signals

## Decision log

- 2026-08-28: use request contexts as the parent of adapter timeouts. Adapter
  timeouts remain local upper bounds.
- 2026-08-28: keep the qBittorrent adapter context-aware at its interface and
  polling boundaries. Its upstream API remains context-free, so an in-flight
  library call cannot be interrupted safely.
- 2026-08-28: remove stack mutation through reflection and `unsafe`. Keep
  standard wrapping and add one safe, idempotent stack carrier to unexpected
  operational errors. Expected outcomes and context cancellation stay
  stack-free. Zerolog emits the captured stack only in operator logs.
- 2026-08-28: future persistent import workers must derive execution contexts
  from the worker lifecycle. An HTTP request context can cover validation and
  durable admission, but it must not own work after the `202` response.
- 2026-08-28: keep notifications asynchronous in a server-owned task group.
  Shutdown closes task intake, waits within the shared deadline, and cancels
  remaining sends when that deadline expires.
- 2026-08-28: use a 15-second shutdown context derived with
  `context.WithoutCancel` so the signal that starts shutdown does not also
  cancel the cleanup context.
