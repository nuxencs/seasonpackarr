# End-to-end harness

Tracks #279.

## goal

One end-to-end test layer runs the real user flow in the Docker Compose
harness: a pinned real autobrr gets an announce line, runs the filter and the
seasonpackarr external webhooks, and fires the import action. seasonpackarr
runs from the release Docker image, hardlinks the episodes that a real client
already has, and imports the pack. The client downloads only the missing
episodes from the seeder, and the pack seeds.

## scope

- harness moved from the torrent client package's test data to `test/harness/`,
  and the helpers that both layers use moved to `internal/daemontest` (#280)
- pinned autobrr service, set up over its REST API, with a committed indexer
  definition and filter config
- seasonpackarr service built from the release `Dockerfile` once for each
  runner call, with a committed config
- partial-pack, complete-pack, and candidate-rejection scenarios for the
  newest supported qBittorrent, Transmission, and Deluge
- runner entries `e2e-qbit`, `e2e-transmission`, `e2e-deluge`, the group
  argument `e2e`, and `list e2e`
- CI job group in the integration workflow
- ADR-0002, Testing Surface terms (end-to-end, integration, CLI tests), the
  `AGENTS.md` Verification section, and the tech-debt tracker

## non-goals

- production code changes or test hooks in production packages
- README filter drift checks (tracked as tech debt)
- importing the filter into autobrr as one JSON file
- a match-rejection scenario, older client versions, an autobrr version matrix
- RSS, Prowlarr backfill, search, and Discord notifications
- a required CI check
- removing or shrinking any integration test

## risks

- autobrr needs an enabled IRC network for a server that does not exist. Its
  reconnect attempts fill the logs and could disable the network or drop
  queued announces.
- The autobrr external webhook timeout must be longer than the seasonpackarr
  match time on a cold inventory.
- autobrr processes announces on a queue. A test that assumes the announce
  call finishes the processing is flaky.
- An autobrr upgrade can change the template rendering. The pin is an exact
  tag and digest, bumped by hand.
- Docker Desktop bind mounts on macOS break hardlinks (ADR-0001). Only the
  named `/data` volume may hold packs.

## decision log

- The harness lives in `test/harness/`, a top-level location that the
  integration layer and the end-to-end layer share. The Go toolchain sees no
  package there, because the folder has no Go files. (#280)
- `internal/daemontest` holds the settings gate and strict mode, the bounded
  waits, the pack and torrent builders, the seeder, and the peer address
  lookup. It has no build tag, so `go build ./...` and `go vet ./...` compile
  it without Docker. The integration fixtures keep the client environment
  names, `requireDaemon`, `importRequest`, and the integration assertions.
  (#280)
- The step order follows the sub-issues of #279. The autobrr and
  seasonpackarr services come in the first qBittorrent ticket, so the first
  end-to-end change already runs the full path. (#280)
- The seasonpackarr image comes from `ci.Dockerfile`. The release workflow
  publishes the image from that file. The plain `Dockerfile` does not build:
  the `\` after `BUILDTIME` continues the `ARG` into the empty line, so
  `COPY go.mod go.sum ./` never runs. This ticket changes no production file,
  so the fix is a separate change. `run.sh` still reads the Go test image from
  `Dockerfile`, which pins the same Go image. (#283)
- autobrr v1.88.0 facts that the driver depends on, from its source (#283):
  - `POST /api/filters` stores only the base filter. The indexer link, the
    external webhooks, and the actions need the update, and the update
    overwrites every field. The filter arrays `resolutions`, `sources`,
    `codecs`, and `containers` are `NOT NULL`, and filter reads omit empty
    arrays, so the driver sends them empty, as the filter import does.
  - The external webhook client has a fixed 120 second timeout
    (`internal/filter/service.go`). No setting changes it. A match on a cold
    inventory took about 2 ms in the harness.
  - The Webhook action ignores the response status, so `PUSH_APPROVED` proves
    only that autobrr sent the import. The client and the disk are the truth.
  - autobrr stores a release only when a filter approves it. A release that
    an external webhook rejects leaves no row, so the candidate-rejection
    scenario (#281) cannot wait for a rejected release. It must prove the
    processing in another way, for example with the candidate request in the
    seasonpackarr log or the torrent server, plus a bounded wait without a row.
  - autobrr drops the host of the announced torrent URL and joins its path to
    the indexer `base_url`.
  - The indexer must exist before the IRC network, or the announce channel
    gets no announce processor.
- The test container runs with `docker compose run --use-aliases`. Without
  it, other containers cannot resolve a `run` container by its service name,
  and autobrr cannot download from the driver. (#283)
- The seeder connects to the client only after the pack is in a download
  state. seasonpackarr returns from the import before qBittorrent finishes its
  check. A seeder that connected during the check stalled the download for
  30 seconds in one of two runs before the fix, because libtorrent backs off from a peer
  that failed. (#283)
- Reconnects to the missing IRC server (#283): in v1.88.0 the handler retries
  up to 25 times with an exponential backoff from 15 seconds
  (`internal/irc/handler.go`). Only a TLS verification error stops it. Only
  `disableNetworkForProxy` changes the stored `enabled` flag
  (`internal/irc/service.go`). The handler, its channels, announce processors,
  and the 128-line queue stay registered when the connection fails. The
  autobrr log of a harness run shows the first connect attempt fail with
  `no such host`, the announce processed 7 seconds later with the network
  still enabled, and the next attempt 15 seconds after the first.
- The candidate-rejection scenario reads the rejection from autobrr's own log
  (#281). `AUTOBRR__LOG_PATH` makes autobrr write zerolog JSON lines to a file,
  and `GET /api/logs/files/autobrr.log` returns them after its sanitizer. The
  debug line `filter rejected release` has the fields `filter`, `release`, and
  `rejections`. The test requires `[external webhook status code] not
  matching: got 200 want: 250`: seasonpackarr answers 200 (no matches) when no
  client episode is compatible, even when it saw an incompatible one. The
  client has a 720p episode of the 1080p pack, so the candidate check reads a
  real inventory with the same title.
- The scenarios share one seasonpackarr process for each entry. Its inventory
  cache lives 30 seconds (`inventoryCacheTTL`), and only an import deletes it.
  `runScenarios` runs the candidate rejection last, so no later scenario gets
  an inventory without its own episodes. (#281)
- The complete pack has no seeder, and its data stays in a temporary folder
  outside `/data`. It can seed only from the hardlinked episodes, so seeding
  plus 0 downloaded bytes proves the reuse. (#281)
- The qBittorrent queue keeps 3 torrents active by default. The complete pack
  is the fourth seeding torrent and stayed in `queuedUP` in the first run. The
  e2e driver turns the queue off through the API, so the shared
  `qBittorrent.conf` and the integration entries keep the default. (#281)
- `client` in `test/e2e/scenarios_test.go` is the per-client interface: config
  name, add, remove, state read, and peer address. The scenarios and the waits
  are generic. `daemontest` got `AssertHardlinked`, `AssertSameBytes`, and
  `QbitSeeding`. `assertDownloadedPack` in the integration fixtures keeps its
  own checks, because it also checks that the downloaded episode is a new
  file. (#281)

## verification notes

- #280: `run.sh list`, `run.sh list all`, an unknown entry, and `-h` print the
  same output as before the move. A tagged run without settings skips, and a
  strict-mode run without settings fails.
- #280 (2026-10-11): `test/harness/run.sh` passed every default entry
  (qbit-4.3.9, qbit-5.2.4, transmission-4.0.6, transmission-4.1.3,
  deluge-1.3.15, deluge-2.0.3, deluge-2.2.0). The only skip is the manual
  category path case on qBittorrent 4.3.9, which that version does not
  support. `go test ./...`, `gofumpt`, `go vet -tags=integration`, and
  `govulncheck ./...` pass.
- #280: the Integration workflow passed every default entry on #287.
- #283 (2026-10-11): `test/harness/run.sh e2e-qbit` passed three times in a
  row after the seeder fix, each scenario in about 9 seconds. With
  `smartModeThreshold: 0.9` the test failed, because autobrr stored no
  release. That failed run saved the autobrr, seasonpackarr, qBittorrent, and
  seeder logs, and the teardown left only the Go cache volume. Without
  settings, `go test -tags=e2e ./test/e2e` skips, and with
  `SEASONPACKARR_TEST_REQUIRE_DAEMONS=1` it fails and names the missing
  settings. `run.sh list` and `run.sh list all` print the same entries as
  before, and `run.sh list e2e` prints `["e2e-qbit"]`. After the review
  fixes (`test(e2e): address review findings`), `run.sh e2e` passed again.
- #281 (2026-10-11): `test/harness/run.sh e2e-qbit` passed two times in a row
  with the partial-pack, complete-pack, and candidate-rejection scenarios, in
  about 18 seconds each. A mutation that made the client episode 1080p failed
  the candidate rejection with `got 230 want: 250` (the match webhook
  rejected it, below the threshold), so the rejection check tells the
  candidate and the match apart. Without settings the e2e tests skip, and in
  strict mode they fail and name the missing settings. `go test ./...`,
  `gofumpt`, and `go vet -tags=e2e` pass. `run.sh qbit-5.2.4` passed after
  the seeder wait moved to `daemontest.QbitSeeding`.
