# DESIGN.md

Design docs in this repo exist to make change safer, not to perform completeness theater.

Read order:

1. `design-docs/core-beliefs.md`
2. `design-docs/index.md`
3. the narrowest design note for the feature you are changing

Design coverage currently focuses on:

- agent-first operating beliefs
- season-pack processing lifecycle
- matching and hardlinking constraints

Verification rule:

- behavior docs should say whether they were checked against code
- speculative ideas belong in plans, not design docs
