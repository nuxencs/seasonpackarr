seasonpackarr autobrr integration reference

- seasonpackarr is intended to be triggered from autobrr external webhook filters
- filter priority matters; seasonpackarr should run before ordinary TV-download filters when the goal is to intercept season packs
- configure two ordered external webhook checks: /api/candidate first with announce name and client name only, then /api/match with the same fields plus torrent bytes
- autobrr shows reorder arrows only after multiple external checks exist; after save and reload, confirm /api/candidate is displayed above /api/match because persisted top-to-bottom display order is execution order
- /api/candidate reads torrent summaries only; a rejection avoids the torrent download and per-torrent file-detail reads
- /api/match parses the torrent, builds an exact side-effect-free import plan, and applies smart mode to actual torrent coverage
- /api/import reuses the accepted plan when possible, hardlinks episodes under the client's import root, and adds the torrent back to the client
- the candidate and match checks normally share one short-lived client inventory; import normally performs no second inventory or file-detail reads
- the filter needs only a single Webhook action for /api/import; do not add a separate torrent-client action, seasonpackarr adds the torrent to the client itself
- changes that alter webhook expectations should update product specs and README
